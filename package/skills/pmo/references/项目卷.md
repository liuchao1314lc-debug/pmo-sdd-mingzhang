# 项目治理规则（项目卷）

> 五域规则。每域按「是什么 / 做什么 / 怎么做」组织，条款编号供裁定引用。
> 统一项只引用通则卷，不另定义。
> 提取边界：本卷只承载跨项目复用的治理机制；产品内容层的具体红线（工作区/存储/媒体/助手/远端的产品规则）不进 skill，产品样板归 deliverables/。

## 一、文档治理（文）

### 是什么

项目文档的目录、命名、状态、模板体系。管文档"放在哪、叫什么、承担什么角色、处于什么状态、用什么模板生成"。文档状态词表见通则卷 #3，版本记法见 #4。

### 做什么

- **文-01 一份文档一个角色**：任何文档只承担一个角色，不越界。五类角色——长期规则／当前事实／功能合同（阶段产出物）／专题合同／历史证据。当前事实不写产品愿景，长期规则不写包身份，历史归档不冒充当前授权。
- **文-02 分层落位**：项目侧文档按架构落 governance/（只事实）与 deliverables/（只内容）；方法与模板在约束包，项目事实与环境资产永不回流进 skill。
- **文-03 索引文档只载指针**：导航/索引类文档（图集索引、入口表）只写文件指针与归属，不写状态、完成度或产品愿景。图集索引结构见通则卷 #13。
- **文-04 模板生成**：产出物用 assets 模板生成，强制上游引用头部（通则卷 #6）；初始化用 assets 初始化模板包生成 governance/ 骨架。
- **文-05 归档隔离**：归档只追加不改写；归档只回答"以前发生过什么、为什么这样决定"，不覆盖上一级当前文档与授权；每条注明日期。归档的口径位次见信息治理 信-02。
- **文-06 维护节奏**：每轮施工结束更新当前事实文档并跑文档一致性检查；每个产出物交付把过程与被替代方案移入归档，当前页只保留仍有效规则；定期核对长期规则是否仍有效。一致性检查失败阻断推进（执法见通则卷 #20）。

### 怎么做

- 初始化按启动卡 Case A 序列＋初始化模板包建目录，按命名规范命名。
- 写任何文档前先判定其唯一角色；越界即拆分。
- 更新当前事实文档前先删已失效内容再追加（防流水账化，见 决-02）。
- 一致性检查核对：文档指针存在、身份一致、归档被索引、口径无冲突。

## 二、信息治理（信）

### 是什么

单一事实源＋术语表＋同义词映射。管"同一信息只在一处定义、其余引用；新词先入表再使用；不同用词但同表意做定义对齐"。术语表结构见通则卷 #2，语义对齐/语言转换点见 #11。

### 做什么

- **信-01 单一定义**：同一信息只在一处权威定义，其余引用，不另立第二份并行定义。状态板的长期边界是规则的事实投影，不是第二处定义。
- **信-02 冲突优先级**（本卷唯一定义处）：口径不一致时按序裁决，不允许反向——用户最新明确决定 ＞ 当前规则/状态板/代码地图（当前事实）＞ 当前或最新交付规格 ＞ 历史归档 ＞ 聊天记忆。用户最新决定由决策与状态治理记入决策记录。
- **信-03 磁盘事实优先**：文档与磁盘事实冲突时，先核实磁盘、再修文档，不能靠记忆猜。
- **信-04 新词先入表**：新词先入术语表再使用；用户不同用词但同表意的做定义对齐（同义词映射）。对齐动作固定在裁定协议的呈报环节（通则卷 #7／#11）。
- **信-05 理解前置（未知不猜）**：动手或下结论前先锚定任务三要素——是什么（身份与边界）、做什么（目标与产出）、怎么做（执行路径）；三要素未确立不抢跑结论、不启动执行（fail-closed）。能力/容量/状态未知时保持 unknown 并保守回退，不按名称、标签、来源猜测，不另建第二份数据绕过。
- **信-06 单一接手入口**：续接以状态板为唯一入口（通则卷 #9），分层读取"入口＋当前所需"，不整集读入；接手路径固定几步，任何一步读不完说明该文档已失控、需要治理。

### 怎么做

- 写结论前先查是否已有权威定义：有则引用，无则立单一定义并登记。
- 口径冲突按 信-02 裁决，并把失败方修成引用，不保留两份并行。
- 新词先查术语表同义词，无则入表再用。

## 三、版本治理（版）

### 是什么

需求/交付物/产品发布版本三轨分离的记法＋身份与准入纪律。管"已生效文档修改走变更、版本升级、旧版保留、禁止静默覆盖；交付物身份可机械核对；分类不是删除授权"。版本记法见通则卷 #4，文档状态词表 #3，生效授予与信任根 #21，重入协议 #8。

### 做什么

- **版-01 禁止静默覆盖**：已生效产出物修改必须走变更流程（通则卷 #8）、版本升级、旧版保留；受影响下游产出物与图标"待复核"（通则卷 #8 变更回流）。
  - **补注（升版/保版统一口径）**：①改写已生效正本的正文或头部→升交付物版本并保留旧版；②独立索引更新可以保版；③历史快照继续指向当时的基线，不溯改；④只同步明确需要迁移的在用引用；⑤校验和用于核对文件身份（不作升版/保版的分流判据）；⑥超出原授予范围的增量先随批裁定再实施，并记录授予依据（头部授予面注记写明哪批裁定授予；三步：增量呈裁→批裁连带授予→注记回填升版）。
  - **补注（旧版保留＝旧版可恢复）**：旧版保留证明旧版可恢复：①保留完整副本；②从可信基线逆向还原并核对旧版校验和——手工重构方案（形式②）须经裁定认可。实现形式随项目版本管理条件。
- **版-02 身份三件套**：任何可运行/可验收交付物固定三件套——唯一位置、身份 metadata（至少含版本标识、来源提交、生成时间、完整性校验）、状态板誊录。身份直接核对 metadata，不从旧聊天复制。
- **版-03 状态领先≠授权授予**：刷新/领先/部署成功是状态推进，不等于升版、发布或验收通过；领先线上不等于发布。升版与发布须用户明确授权（权-02）。**"升版"消歧（本卷唯一定义点）**：此处"升版"指产品发布版本升版（＝发布，须用户明确授权，通则卷 #4）；交付物版本升级随版-01 变更流程走，不另设授权事件。
- **版-04 回退与残留纪律**：旧版改名/回退路径必须存在；禁止无回退的覆盖；任一步失败恢复原真相，恢复失败保留全部证据并停手；来源不明的候选/残留不覆盖、不复用、不删除；未发布候选不得使用。
- **版-05 分类不是删除授权**（本卷唯一定义处）：旧命名/遗留 artifact 只分类导航，参考四类——A 持久格式与旧数据兼容合同／B 名字旧但当前正式在用／C 退役隔离候选／D 承担门禁证明的样本。分类表不是删除清单；任何清理另立变更裁定，先证明兼容与门禁价值。静态"零引用"不等于死代码（可能被动态加载）。
- **版-06 准入诚实**：未验证/未准入的制品（未 clean commit、未合入、未独立复审）只能标"未准入"，不冒充已生效能力；源码推送不等于升版、不等于发布。
  - **补注**：可用包快照记录当前包内容，标记未准入并如实记录 clean commit 缺失。是否按降级路径继续，依既有纪律处理。
- **版-07 防陈旧覆盖**：过期、重复、迟到结果不能按身份覆盖新任务；复制不携带执行身份。

### 怎么做

- 修改已生效文档前：发起变更→裁定类型（通则卷 #8）→交付物版本升级→保留旧版→下游标待复核。
- 交付物刷新：门禁通过→clean commit→生成→校验 metadata→同步状态板→归档；跳任一步即身份失真。
- 清理旧 artifact 前：查分类表→另立变更规格→证明兼容→裁定→执行。

## 四、权限治理（权）

### 是什么

agent 的写边界。管"四层谁写谁读、agent 能写什么、只能读什么、哪些动作必须先呈报裁定、哪些必须用户明确授权"。三权分立与信任根见通则卷 #21，约束包组件分工 #20，环境供给层写权威 #16（统管台账＋词表两资产）。

### 做什么

- **权-01 四层写读权威**：skill 只带方法不带事实；约束包部署实例使用中只读，路径见部署回执，改源再同步；governance/ 只项目事实，agent 按协议写；deliverables/ agent 出草稿、用户授予生效；环境级台账/词表写权威按通则卷 #16。项目事实与环境资产永不回流进 skill。
- **权-02 授权语义**（本卷唯一定义处）：授权须用户本人明确说出对应动作短语，不能被"继续/验收通过/交接/发包要求"替代；持续授权须显式声明范围，范围外动作不包含；高风险动作每次单独授权，不能靠上一次"可以"延续。**目标对齐：agent 以用户目标为唯一执行目标；任何偏离或新增的其他目标（含自生子目标、优化目标、范围扩展）必须先呈报用户裁定批准（#7）后执行，不自行追逐；agent 自主权限于执行路径与修理计划（权-07），不及于目标本身。**授权语义写进项目规则，不只留在聊天。
- **权-03 高风险动作清单**：删除、发布、付费、外部写入、不可逆、账号密钥、用户资料清理、改变产品主心智、删除用户可见能力、接入第三方/计费、产品部署——必须先取得用户明确授权（此处"部署"指产品部署/生产环境；在项目内按宿主适配方式部署约束包是治理动作，不在此列）；项目内普通、可撤销动作可自动执行。
- **权-04 三权分立**：生产权 agent（只出草稿）／校验权独立检查者（只读、与生产者分离、不共享上下文）／生效权用户（裁定授予）。agent 不能自我授予生效或伪造决策记录。
- **权-05 先只读后授权写**：探测/选择阶段只读；真实路径、范围、写权限通过后才写；写入须读回核验，回执为真相（决-01）。删除偏好可逆（回收站/移除入口），不递归、不未经授权永久删。
- **权-06 写入内容边界**：产出物与记录不携带密钥、内部路由、内部成本、隐藏推理等敏感内容；只呈现公开合同与公开事实。
- **权-07 用户角色边界**：用户只做复测与授权两件事；agent 全权拥有修理计划与推进执行；门禁裁定、生效与高风险授权回到用户。

### 怎么做

- 任何写入前先判定目标层与权威（权-01）；跨层或高风险先呈报裁定（通则卷 #7）。
- 高风险动作前核对用户明确动作短语授权；持续授权核对范围。
- 生效授予经裁定协议第 3 步写决策记录（通则卷 #7／#21），hook 校验生效项与决策记录一一对应。

## 五、决策与状态治理（决）

### 是什么

决策记录＋项目状态板，独立成域。管"每次裁定内容与依据留存（含大白话原文对照）；状态板记录当前阶段、待裁项、阻塞项、被什么打断，是续接唯一入口；完成判定诚实，证据高于口头"。状态板结构见通则卷 #9，裁定协议 #7，生效授予 #21，重入 #8，语言转换点 #11。

### 做什么

- **决-01 真相判据**（本卷唯一定义处）：口头"已完成"不算；执行回执＋项目后状态才是真相。成功须经正式保存＋独立读回＋核验；自动门/checkbox 不替代未覆盖的人眼验收。
- **决-02 状态板内容纪律**：状态板只写当前结论、风险、下一步，不写阶段流水账；更新前先删已失效内容再追加；已交付基线与历史阶段移入推进记录/归档。
- **决-03 决策记录留存**：每次裁定记录内容、依据、大白话原文与专业表述对照；决策记录是信任根，写保护，agent 不能自我授予或伪造；写入通道＝裁定协议第 3 步专属动作（通则卷 #20／#21）。
- **决-04 验收诚实**：本机交付不等于整项真实验收完成；部署成功不等于真实验收通过；用户实机验收待续如实写"待续"，不冒充已完成；故障归因到具体端并附持久化证据，不接受推测性结论。
- **决-05 根因优先**：同一问题连续两轮没解决，停止打补丁，回到根因裁定（状态所有权/数据关系/执行链路）；结构性缺陷偏好一次有界重构（分阶段＋门禁＋验收）而非连续小包；bug 重入先归因裁定（通则卷 #8）。
- **决-06 续接唯一入口**：新会话先读状态板定位当前阶段与待裁项，不直接进归档或专题；归档里的"当前/下一步/必须做"只属于当时，不是今天的授权。

### 怎么做

- 每轮施工结束：更新状态板（当前/风险/下一步）＋推进记录（已交付基线）＋跑一致性检查。
- 裁定发生：呈报（大白话＋专业对照）→用户裁定→记入决策记录→生效并更新状态板（通则卷 #7）。
- 新会话接手：读状态板→定位阶段→读所需规则与当前阶段卡。
