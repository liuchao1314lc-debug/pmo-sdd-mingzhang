# 流程治理规则（流程卷）

> 卡目录＋总流程图＋十张阶段卡＋承载类型特定治理附录（按形态唤起）。卡通用五字段：入口条件 / 动作 / 产出物及模板 / 出口判据 / 裁定点（通则卷 #5）。
> 通用规则（ID 链/门禁/裁定协议/重入协议/图审批/对账）见通则卷，卡内只引用不重复。
> 出口判据均写明查什么文件、对什么字段；定位读当前卡，不整卷读入。

## 卡目录

启动 → MRD → PRD → 架构 → 模块 → 组件 → UI → 开发 → 联调测试 → 迭代

## 总流程图（通则卷 #10 记法）

```text
启动 -> 〔门：governance 骨架＋状态板就绪〕 -> MRD
MRD -> 〔门：需求确认＋全景图＋边界图＋对账〕 -> PRD
PRD -> 〔门：功能图＋双向覆盖〕 -> 架构
架构 -> 〔门：架构图＋对账＋载体决策〕 -> 模块
模块 -> 〔门：模块图＋双向覆盖〕 -> 组件
组件 -> 〔门：组件图＋复用＋双向覆盖〕 -> UI
UI -> 〔门：UI 图＋双向覆盖〕 -> 开发
开发 -> 〔门：实现＋回执＋clean commit〕 -> 联调测试
联调测试 -> 〔门：真实验收〕 -> 迭代
迭代 -> ?新增需求 -> ↩ MRD
迭代 -> ?需求变更 -> ↩ 原阶段
迭代 -> ?bug·执行偏差 -> ↩ 开发
迭代 -> ?bug·定义缺陷 -> ↩ 原阶段
```

文字语义：迭代是变更重入机制，不是线性终点。新增需求赋新 ID 走全链；需求变更原 ID 原地改＋下游标待复核；bug 先归因——执行偏差回开发（文档不动），定义缺陷转需求变更（通则卷 #8）。跳阶段与回退见通则卷 回退与跳阶段节，按强度档位（#22）。

## 阶段卡

### 启动

- **入口条件**：A 新建——用户提出产品目标与材料、现场无既有项目产物；B 接续——用户请求接管既有项目（现场有既有 deliverables/代码或 governance）。宿主环境就绪（约束包源可用）。
  - **入口分诊（探针，机制归本卡，续接路由引用）**：B 接续跑会话级廉价探针（机械可查）——① 状态板存在可读；② 当前阶段∈十阶段；③ 状态板身份指针指向物存在；④ 已生效项抽查有决策记录（#21）；信-03 核对磁盘是探针一部分。探针即 B 态分诊器（卡内不另写分诊）：通过＝B1、状态板缺失＝B2、存在但失败＝B3。探针通过→续接路由直达当前阶段（B1）；失败→进 Case B。接管级完整核验（查全部承重地板 #21）只有被探针挡进来才一次性跑，按档位比例化（#22），不做重闸门。A 新建无既有基线、不跑探针，直接 Case A。
- **动作**：
  - **Case A 新项目启动**：按初始化序列——探测宿主能力→生成部署回执（写明降级项）→降级触及承重先经 #7 裁定接受手工替代→按宿主适配方式部署约束包实例（带版本戳，实际路径记入部署回执）→模板包生成 governance/ 骨架→选强度档位→首次初始化环境级供给台账/能力词表→状态板置"启动完成"。
  - **Case B 已有项目接续**（三态各写序列；共同原则：路由到实际当前阶段，不强制回 MRD、不伪造新 ID，ID 链不污染）：
    - **B1 基线完整**（探针通过）：承重基线可信→路由到当前阶段；接管级核验不跑。
    - **B2 棕地**（状态板缺失，有项目无 governance）：① 读既有 deliverables/代码（磁盘事实 信-03）→② 模板包建 governance/ 骨架（A 骨架子集）→③ 既有产出物纳管登记标"草稿"（#3，登记是 agent 产出）→④ 反推当前阶段定位（语义判断，只作呈报）→⑤ 批量呈报纳管清单＋阶段定位、标"待裁"（#3／#7）→⑥ 用户批量裁定追认：追认项"待裁→已生效"（决策记录注记"纳管追认"，一份裁定覆盖一批、可载批量清单），不追认项"待裁→已作废"（#3）；阶段定位经裁定才写状态板→⑦ 接管级承重核验→路由到当前阶段。
    - **B3 残缺/冲突**（状态板存在但探针失败）：① 信-03 核磁盘事实→② 冲突按 信-02 优先级裁、连续两轮未决停补丁回根因（决-05）→③ 修状态板/文档（先删失效再追加，决-02）→④ 接管级承重核验→⑤ 路由到当前阶段。
- **产出物及模板**：A——governance/ 治理配置、绑定事实、术语表骨架、状态板、决策记录目录、对账表目录、部署回执（assets 初始化模板包）。B2——governance/ 骨架（A 子集）＋纳管登记（既有产出物清单）＋阶段定位呈报＋纳管追认决策记录；B3——修复后状态板/文档＋冲突裁定记录；B1——无新增（路由）。
- **出口判据**：
  - A：查 governance/ 骨架齐全（配置/术语/状态板/决策记录/对账表/回执俱在）；状态板当前阶段＝MRD、续接入口就绪；部署回执写明宿主/组件/版本/降级项；档位记入治理配置＋决策记录。
  - B1：探针通过＋已路由到当前阶段（状态板可信）。
  - B2：骨架已建＋纳管裁定完成（追认项已生效有决策记录、不追认项已作废）＋阶段定位经裁定写状态板＋接管级承重核验过＋路由到当前阶段。
  - B3：冲突已裁、磁盘与文档一致（信-03）＋状态板修复就绪＋接管级承重核验过＋路由到当前阶段。
- **裁定点**：
  - A：强度档位选定（用户裁定 #7）；降级触及承重须显式接受手工替代（#21）；约束包部署是治理动作非高风险（项目卷 权-03 注）。
  - B：接续核验结论裁定；缺口处置裁定；B2 阶段定位确认（反推属语义判断，呈报经 #7 裁定才写状态板）；纳管追认（批量呈报→用户批量裁定，决策记录注记"纳管追认"，#7／#3／#21）。

### MRD

- **入口条件**：启动出口判据通过；状态板当前阶段＝MRD。
- **动作**（多轮迭代环；①—③ 累积循环，④ 判据达标才进 ⑤—⑦）：
  - ① **收集**：多轮交流采集用户目标与场景；原始沟通暂存 MRD 草稿（含未确认料）；待确认项主载体＝MRD 草稿内"开放问题清单"，状态板只指进度、不另立清单（单一事实源，项目卷 信-01）。同步采产品类型（关乎边界/展现）与面向用户情况（自用 vs 运营用户，关乎要不要后台）——现实开发常省略，此阶段补上。原始料极薄时，采集可取"假设显式标注＋开放问题批量确认"形态；假设标注与确认裁定不省。
  - ② **分析**：把粗料析成需求；分析产物须满足五条可查属性（治理纪律，非操作教程）——区分用户需求与产品需求、挖真实动机不照搬原话、抽象诉求转可测场景、标假设与待确认项、划边界（in/out/deferred）。可选指引见 [OO 方法指引](OO方法指引.md)（不进出口判据）。
  - ③ **呈报确认累积赋 ID**：分析结论经 #7 呈报、#11 语义对齐后向用户确认；确认项累积赋需求 ID（#1）；未决项回写开放问题清单。迭代中已确认需求再改走 #8 修订层（R-001→R-001.1），不改 ID、不静默覆盖。
  - ④ **确认完成判据**（④→⑤ gate，机械可查）：开放问题清零（或逐项经 #7 裁定 deferred）＋需求范围经 #7 裁定；范围裁定即确认完成事件。
  - ⑤ **全景图**：建需求级全景流程图（#12 树根，黑箱视角、业务用语）；业务/系统级用户走线一次梳理在本阶段（PRD 不重梳，功能级分解留 PRD）。
  - ⑥ **边界图**：建边界图登记全部外部能力关系（#14，能力—载体两层）。
  - ⑦ **对账**：跑能力供需对账（#18），含外部 prior-art 粗扫（深度按档位 #22）。
- **产出物及模板**：MRD（产出物模板，头部 #6，需求 ID R-）；需求级全景流程图（树内根，图模板，#12）；边界图（根伴视图，图模板，#14）；需求×供给对账表。
- **出口判据**：
  - 需求确认（④判据）：开放问题清零或逐项经 #7 裁定 deferred；需求范围经 #7 裁定（范围裁定即确认完成事件）。
  - 需求与图：查 MRD 每需求有唯一 ID；全景流程图过 #19 三层闭环审批、登记进 #13 索引；全景图节点与需求 ID 双向覆盖（每节点锚 R-ID、每 R-ID 入图——根图无上游，覆盖即与自身需求清单对账；结构半机械可查，归 #20 执法）；记法封闭集照 #10；全景图涉外部能力的边按 #14 锚定边界图能力 ID（两图互引、#19 整体闭环）。
  - 边界与对账：边界图外部边四属性齐全（#14）、过图审批（#19 边界图特殊替换）；对账表每需求处置状态不空（#17）；MRD 出口对账门禁通过（#18）。
  - 语义硬线（随 #19 呈报、检查者＋用户裁）：全景图停业务/系统级——业务用语、无技术语言、无功能分解颗粒；信息运行脉络写进节点描述（节点语义，#10 文字管语义），不进记法结构符（#10 封闭集不动，层级由粒度硬线管）。
  - 补漏自查前置（agent 先自查、门禁复核；非第二道门禁、非新统一项；四项各指回上方判据）：① 需求漏——用户目标/场景有缺口未承接成需求（语义自查）；② 能力漏——外部能力依赖未全部入边界图（对 #14 全部外部能力关系）；③ 处置漏——外部能力需求处置状态有空（对 #17 必带不空）；④ 覆盖漏——全景图与需求 ID 双向覆盖缺口（对结构半）。
- **裁定点**：需求范围裁定；全景流程图审批裁定（#19，含语义硬线）；边界图"依赖存在、接入未定"项呈报（决策引用指向本次门禁裁定，#14）；对账待裁/自建项裁定（#7，自建须举证 #18）。

### PRD

- **入口条件**：MRD 已生效＋出口门禁通过。
- **动作**（七步）：
  - ① **读上游**：MRD 已生效产出物＋全景图，按需加载沿出处、不整读。
  - ② **需求分解**：父需求按产品视角拆子需求——子需求赋新 ID（#1 修订层禁作子需求编号），父子关系经头部上游引用；分解只到"产品要满足什么"粒度，不产出功能方案。
  - ③ **功能定义**：每需求（含子需求）定义承载它的产品功能——功能＝用户可感知的能力单元，每功能锚 ≥1 R-ID。
  - ④ **功能取舍**：保留/合并/拆分/deferred——deferred 须裁定并记入范围外清单（继承 MRD in/out/deferred 口径）。
  - ⑤ **画功能图**：节点＝功能，出处标注 `节点名[源:G-xxx/节点ID]` 指向全景图节点——树的第一跳（#12 树根→功能层，#10 语法）。
  - ⑥ **PRD 落稿**：功能规格每功能四件——名称、锚定 R-ID、用户可见行为描述、验收口径种子（给联调测试反向追溯）；范围 in/out/deferred 更新。可选指引见 [OO 方法指引](OO方法指引.md)（不进出口判据）。四件须满足可查属性（治理纪律非操作教程）：
    - **行为描述四类场景位齐全**（正常路径＋异常/错误＋边界/极限＋状态流转）：描述位齐＝结构半（自查可查），覆盖充分性＝语义半（随 #19 审批裁）。状态走文字/节点描述（#10 文字管语义），不新增图类——封闭集四符号本可表达状态迁移（状态＝节点、迁移＝`->`、守卫＝`?条件`），后续阶段认定状态视图有价值时用既有符号画，不为图类名开框架口子。
    - **验收口径可测二值、分两类**：机械可测（带数字、pass/fail 自动判定）＋用户验收项（体验类标"用户验收"，对应联调测试用户复测 权-07）；防体验类硬凑数字。不教 Given/When/Then 操作教程。
    - **NFR 质量目标随所属入验收口径**：产品级入 PRD 总验收口径、功能级入该功能验收口径，不另立独立 NFR 文档（防两处并行，项目卷 信-01）；NFR 目标入架构入口约束（前向钩子，架构卡接住）。
  - ⑦ **呈报**：功能清单＋功能图过 #19 三层闭环审批。
- **产出物及模板**：PRD（头部上游引用 MRD）；功能图（节点映射 MRD 全景图节点，#10／#12）。
- **出口判据**：
  - 双向覆盖：功能↔需求双向覆盖（每功能锚 ≥1 R-ID、每 R-ID 有功能承载，#20"覆盖一致"机械可查）；子需求皆新 ID 非修订层（#1）。
  - 功能图：节点出处标注语法齐全（#10）、过 #19 三层闭环审批、登记 #13 索引。
  - PRD 硬线（修正版，随 #19 呈报、检查者＋用户裁）：排除实现选择（用什么技术/载体/实现语言——归架构载体裁定），不排除质量目标（NFR 做到多好——入验收口径）；PRD 停功能级 WHAT＋WHAT-WELL，技术 HOW 归架构门禁（MRD 业务级硬线下探一层，#12 一图一层）。"声音被环境策略阻止"属用户可感知异常条件，入行为描述，非实现混入。
  - 功能规格达标：step6 四件齐全＋可查属性达标（四类场景位结构半、覆盖语义半随 #19、验收口径两类可测、NFR 随所属入位）。
  - 补漏自查前置（agent 先自查、门禁复核；非第二道门禁、非新统一项；items 指回上方判据无独立内容，存在性由检查者＋出口判据覆盖）：① 场景漏——四类场景位有缺（对 step6 行为描述结构半）；② 口径漏——验收口径不可测/体验类未标用户验收/NFR 目标缺位（对 step6 验收口径）；③ 覆盖漏——功能↔需求双向覆盖缺口（对 #20 结构半）；④ 实现混入——技术方案/载体/实现语言混入（对硬线修正版）。
- **裁定点**：功能取舍裁定（含优先级/deferred，记入范围清单；优先级方案 P0/P1/P2 或 MoSCoW 实例化，不教技术）；需求分解方案；功能图审批裁定（#19，含硬线修正版＋覆盖语义半）。

### 架构

- **入口条件**：PRD 已生效＋门禁通过；接住 PRD 前向钩子——NFR 质量目标入架构入口约束（PRD 卡 step6）。
- **动作**（七步）：
  - ① **承载类型＋复杂度门**：读 MRD 产品类型／面向用户＋PRD NFR 入口约束，选定产品承载类型（app／小程序／web／agent／桌面等，开集非封闭枚举）；再视需求裁框架 vs 简单底座（复杂度门）。承载类型与复杂度门属**难改顶层决策**（代价高、可经变更重入翻案），经 #7 裁定；产品侧克制锚架构裁定点 #7。
  - ② **唤起形态 overlay**：按选定形态唤起承载类型特定治理（按需加载，指针→本卷附录对应形态锚点；普遍规则不动，只叠形态特定考量）。
  - ③ **条件分层**：底座→最小雏形；框架→容器级分层（分层技术属产品内容，本卡只治理不教技术）；出处标注指向功能图节点（树纵向一跳，#12／#10）。可选指引见 [OO 方法指引](OO方法指引.md)（不进出口判据）。
  - ④ **其他支持**：补需求/NFR 隐含的支持块（非必要不做需求外围治理，除非用户要求）；外部能力载体接入按 #14／#18。
  - ⑤ **架构图**：画架构图（节点＝架构单元，出处标注 `节点名[源:功能图ID/节点ID]` 指功能图，#10）；底座也出图——不豁免只降粒度，照样进 #13 索引、挂功能图出处，图集不断链、不随复杂度门打折。
  - ⑥ **架构出口对账**：跑架构出口对账（#18）——功能 ID 覆盖＋外部载体接法（能力—载体两层投影：怎么接、接多少，#14）＋**NFR 逐条回应**（PRD 每条 NFR 目标在架构有明确回应、逐条对照可查：形态/分层/支持块如何满足；实测在联调测试 决-04／权-07，架构答设计上怎么满足、联调答实际上满足没）。
  - ⑦ **载体裁定更新边界图＋呈报**：载体选择经 #7 裁定更新边界图（#14，决策状态"已定"挂决策引用）；架构方案＋架构图过 #19 三层闭环审批呈报。
- **产出物及模板**：架构文档（头部上游引用 PRD）；架构图（节点映射功能图，#10／#12）；架构出口对账表（功能 ID＋载体＋NFR 逐条回应）。
- **出口判据**：
  - 覆盖与图：查架构覆盖功能 ID；雏形单一抽象层级不混（#12，底座降粒度不豁免图）；架构图过 #19 三层闭环审批、登记 #13 索引；出处标注语法齐全（#10）。
  - 对账与载体：架构出口对账门禁通过（#18）；已定外部能力载体决策状态更新为"已定"并挂决策引用（#14）；NFR 逐条回应（PRD 每条 NFR 目标在架构有明确回应、逐条对照可查；实测留联调测试）。
  - 克制自查（产品侧克制，锚架构裁定点 #7，不挂 #21/#22 档位）：支持块非需求/NFR 隐含则不做，除非用户要求；档位不缩放产品复杂度（简单工具配重治理、复杂产品配轻治理均合法），复杂度门是架构裁定内容、不是档位维度。
- **裁定点**：承载类型与复杂度门裁定（难改顶层决策，#7）；架构方案裁定；载体选择裁定（#7，挂决策域）；自建举证（#18）。

### 模块

- **入口条件**：架构已生效＋门禁通过。
- **动作**（七步）：
  - ① **读上游**：架构已生效产出物＋架构图，按需加载沿出处；架构图多张时分架构节点读。
  - ② **模块划分**：逐架构节点拆模块——模块＝职责内聚的能力单元，每模块锚定一个架构节点出处（`节点名[源:架构图ID/节点ID]`，#10）；划分只出"职责与边界"，不出内部设计。可选指引见 [OO 方法指引](OO方法指引.md)（不进出口判据）。
  - ③ **分片**：默认一架构节点一张模块图（纵向细化单位，这张图回答的问题＝该架构节点的内部模块划分）；节点内模块过多时横向分片为兄弟图，分片边界＝职责簇（内聚的模块群）；量性阈值随档位（#22 干跑测定）；每张片图登记 #13 索引、上游指架构图节点——横向分片第一次真用就在这步（#12）。
  - ④ **接口与依赖**：每模块定三件——职责（管什么）、接口（对外提供什么）、依赖（依赖哪些模块/外部能力）；模块间依赖两端齐全（#19 对外＋对内）；涉外部能力的依赖锚定边界图能力 ID（#14）——模块常是外部能力的接入点，消费边界图 ID、边界图唯一事实源地位不动；模块不跑 #18 对账（MRD/架构两处出口门禁已做）。
  - ⑤ **覆盖核销**：架构图每个节点已声明"展开为某模块图"或"到此不再展开"（声明在架构图上，#12 节点映射）；模块图与架构节点双向覆盖——#20 覆盖一致在这一步执行（跨图执法，非图自身审批）。
  - ⑥ **模块文档落稿**：每模块五件——名称、锚定架构节点、职责声明、接口、依赖；头部照 #6（上游引用架构、需求 ID 沿链）；文档不出现类名/函数/库选择（硬线见下）。
  - ⑦ **呈报**：各片模块图过 #19 三层审批＋模块划分裁定；呈报可整批或按架构节点分批（项目大时），每批经 #7。
- **产出物及模板**：模块文档（头部上游引用架构）；模块图（节点映射架构节点，#10／#12）。
- **出口判据**：
  - 覆盖：架构节点展开声明与实际模块图一致（#12 节点映射）；每模块图锚架构节点出处、每架构节点有着落——双向覆盖机械可查（#20 覆盖一致，跨图执法）。
  - 图：单一抽象层级不混（#12）、过 #19 三层、各片入 #13 索引。
  - 依赖：两端齐全（#19 对外＋对内）；涉外部能力依赖已锚边界图 ID（#14）。
  - 模块硬线：无类/函数/库级实现内容——停"职责与接口"，组件卡才下沉；语义半随审批裁（#12 一图一层在模块层实例，PRD 先例）。"状态机/时间戳校准"沿已生效架构职责判职责描述，限于转述已裁职责，非实现混入。
  - 分片：每张片图登记 #13、上游指架构图节点。
  - 补漏自查前置（agent 先自查、门禁复核；非第二道门禁、非新统一项；items 指回上方判据无独立内容，检查者＋出口判据已覆盖，不另立统一项）：① 覆盖漏——架构节点展开声明与实际模块图缺口（对覆盖判据）；② 依赖漏——依赖两端不齐全/外部能力未锚边界图 ID（对依赖判据）；③ 分片漏——片图未登记/上游未指架构节点（对分片判据）；④ 实现混入——类/函数/库级内容混入（对模块硬线）。
- **裁定点**：模块划分裁定（含分片方案：几图几片）；模块图审批裁定（#19）。

### 组件

- **入口条件**：模块已生效＋门禁通过。
- **动作**（七步）：
  - ① **读上游**：模块已生效产出物＋模块图（各片），按需加载沿出处。
  - ② **组件划分**：逐模块拆组件——组件＝有明确接口、可独立实现与对接的单元；每组件锚定模块图节点出处（`节点名[源:模块图ID/节点ID]`，#10）；只出"边界与对接"，不出代码设计。可选指引见 [OO 方法指引](OO方法指引.md)（不进出口判据）。
  - ③ **来源处置判定**（#16/#17 首次正面交叠）：每组件标处置状态（#17 四态词表复用、非 scope 扩展——#17"外部能力需求"scope 一字不动，应用落组件层；不空）——已复用（台账有且已验证）／待获取（台账有但未验证/需接入）／自建（须举证 #18：台账与外部都没有、或有但不用，引架构出口对账表＋台账现状）／待裁（呈报）；拟复用"声称有"条目时，核实授予与复用裁定合并一次呈报——一次 #7 裁定授权两写：决策记录（#7 步 3 专属动作）＋台账授予字段（#16 用户通道），通道各自走；不许跳过核实直接复用（已复用必须已验证，声称有不算，#16）。
  - ④ **组件图**：节点＝组件，出处指模块图节点；默认一模块一张组件图，组件过多按职责簇横向分片（阈值随档位 #22）；各片入 #13 索引。组件同层合片：默认单节点图无内部结构时，可并为职责簇片；偏离默认的方案随批呈裁。

  - ⑥ **组件文档落稿**：每组件六件——名称、锚定模块、职责、接口、依赖、来源处置（台账 ID 或自建）；头部照 #6（上游引用模块、需求 ID 沿链）；文档只管接口面（硬线见下）。
  - ⑦ **呈报**：组件图过 #19 三层＋组件划分＋复用/自建裁定（#7）。
- **产出物及模板**：组件文档（头部上游引用模块）；组件图（节点映射模块图节点，#10／#12）。
- **出口判据**：
  - 覆盖：模块节点展开声明与实际组件图一致（#12 节点映射）；组件图↔模块节点双向覆盖（#20 覆盖一致，跨图执法）。
  - 来源：每组件处置状态不空（#17）；已复用项全部指向台账"已验证"（声称有不算，#16）；自建项有举证（#18）。
  - 依赖：两端齐全（#19 对外＋对内）；跨模块依赖全部经模块接口（无私接）；外部能力锚边界图 ID（#14）。
  - 图：单一层级不混（#12）、过 #19 三层、入 #13 索引。
  - 组件硬线：函数级实现细节禁止；组件内部类结构非门禁物（文档不要求描述、写了也不查，文档只管接口面）；新增技术选型不在组件层私定——难改顶层决策上浮架构裁定点（#7 呈报，难改/可替换归类属语义判断、agent 提议归类用户裁，归"改基线"走 #8 回流），可替换常规依赖归开发；语义半随审批裁。
  - 补漏自查前置（agent 先自查、门禁复核；非第二道门禁、非新统一项；items 指回上方判据无独立内容，检查者＋出口判据已覆盖，不另立统一项）：① 覆盖漏——模块节点展开声明与实际组件图缺口（对覆盖判据）；② 依赖漏——依赖两端不齐全/跨模块私接/外部能力未锚边界图（对依赖判据）；③ 复用漏——处置状态空或已复用指向声称有（对来源判据）；④ 实现混入——函数级细节/组件层私定技术选型（对组件硬线）。
- **裁定点**：组件划分裁定（含分片方案）；复用/自建裁定（含"核实并复用"合并呈报，#7）；组件图审批裁定（#19）。

### UI

- **动作**（七步）：
  - ① **读上游**：组件已生效产出物＋组件图（各片，结构轴直接父）＋功能图（行为轴跳级祖先，#12 纵向链 功能→架构→模块/组件/UI），双上游两轴各自按需加载沿出处。

  - ⑤ **素材来源处置＋高风险标记**：素材（图标/矢量/imagery/组件库等外部视觉资产）来源处置＝组件卡来源处置模式的素材域实例、方案级粒度（不落逐像素）——#17 四态语义照用（已复用/待获取/自建/待裁，不空、scope 不扩展）；无素材需求域显式声明"无需求（四态不适用）"附理由，"不引入"非四态词；复用现成组件库/矢量库优先，接组件库本身（TDesign/Ant 等）＝现成模块入台账走 #16 双通道复用路径（与组件卡同构）；脱离已裁定规格的实现侧自由手画/手写＝自建须举证，引 #18 自建举证口径（架构出口对账表＋台账现状）作证据、不新跑对账轮次（组件卡先例：不跑 #18 只引证据），遵循规格的自绘/再生合法。高风险标记：触权-03 清单（改变产品主心智/删除用户可见能力等）逐条标记（语义判断 agent 提议用户裁）；接入第三方若触权-03（计费类）照高风险走。

  - 回环：待复核清零（#3：复核通过→已生效；需重裁→待裁经 #7 裁定→已生效/已作废，严格按状态机不越态）。
  - 链：回溯链账面核对不失真（#19 整体层＋#13 索引）。
  - 记录：状态板打断与回归更新为"已回归"、决策记录在案（#9／#7）。关闭核验操作提示（非新判据）：按实际变更检查快照与校验和；文本搜索（如旧版本号）只用来定位待核引用，命中逐条归类（live 同步／历史冻结），不作覆盖或过关判据。
  - 补漏自查前置（agent 先自查、门禁复核；非第二道门禁、非新统一项；items 指回上方判据无独立内容，检查者＋出口判据已覆盖，不另立统一项）：① 类型漏——未裁先动工（对类型判据）；② 回流漏——下游漏标（对回流判据）；③ 关闭漏——链失真即关闭/待复核未清零（对链＋回环判据）；④ 登记漏——打断未记状态板（对记录判据）。
- **裁定点**：重入类型与重入点裁定（#7／#8）；新增能力触发下游组件卡来源处置裁定（复用/自建权威在组件卡裁定点／动作③，迭代只路由不重裁；纯文档类变更不走组件卡、不触发此项）；发布授权与发布号授予（#4 既有项——门禁不含发布、发生地非触发器（通则卷 #4），若在此出口发布则在此裁）。

## 附录 · 承载类型特定治理（按形态唤起）

> 普遍规则（架构卡七步＋通则卷）不动，本附录只叠形态特定治理考量，按需加载：架构卡 step2 按选定形态唤起对应节，锚点＝形态名稳定标题。
> **示例非封闭枚举**：现落 agent／小程序／web 三节示例；新形态加 overlay 节即可，普遍规则一字不动。承载类型是开集（纳新），与 #1 类型码闭集（封口防 ID 漂移）方向相反、各管各。
> overlay 装治理考量、不装技术教程（PMO 不生产产品内容）。每形态节固定三件套：外部关系（→#14 边界图）／NFR 与入口约束／触发裁定（→架构卡裁定点）。

### agent

- **外部关系（→#14 边界图）**：工具接口、MCP、外部能力（模型 API／检索／邮件等）全部入边界图，能力—载体两层（未定/已定/已替换），外部边四属性齐全（#14）。
- **NFR 与入口约束**：响应时延、可靠性、成本/额度、安全边界等质量目标入架构入口约束（承 PRD NFR），架构逐条回应（step6）。
- **触发裁定（→裁定点）**：复杂度门——workflows vs agents、框架 vs 简单底座，视需求裁定（难改顶层决策，#7；非必要不增复杂度）；MCP/工具载体选择与对账（#18，自建须举证）。

### 小程序

- **外部关系（→#14 边界图）**：宿主平台（微信/支付宝等）作为外部载体入边界图，平台能力（登录/支付/分享/云开发）能力—载体两层登记（#14）。
- **NFR 与入口约束**：平台审核规则、分发渠道、包大小限制、平台 API 约束入 NFR/架构入口约束，架构逐条回应（step6）。
- **触发裁定（→裁定点）**：宿主平台载体选择（难改顶层决策，#7）；平台能力接入对账（#18）。

### web

- **外部关系（→#14 边界图）**：只登记实际依赖——浏览器宿主 API、实际接入的第三方服务入边界图，能力—载体两层（未定/已定/已替换），外部边四属性齐全（#14）；不预登未用依赖。
- **NFR 与入口约束**：浏览器兼容范围、加载/交互时延、安全边界等质量目标入架构入口约束（承 PRD NFR），架构逐条回应（step6）。
- **触发裁定（→裁定点）**：托管载体选择裁定（#7）；第三方服务接入对账（#18，自建须举证）；渲染形态（单页/多页/服务端渲染等）不一预判难改，确属难改时随架构呈裁（架构卡裁定点）。
