# Codex 宿主绑定

Codex 从目标项目的 `.agents/skills/pmo/` 加载 PMO。在项目根目录用 `$pmo` 加上当前动作进入对应路由。回执登记项目副本的实际路径、Codex 版本、包版本和来源提交或快照。已预装的副本先核对版本、内容、OO 指引和动作指针，核对一致时可沿用。

| 组件 | Codex 实态 |
| --- | --- |
| skills／方法 | 项目级 `$pmo`，含三卷、OO 可选指引和模板。 |
| rules／声明 | 声明随 PMO 加载。项目未配置常驻规则时，按实际登记降级。 |
| hooks／强制 | 当前适配未部署强制写保护或自动执法，按下表核验。 |
| agents／角色 | 项目另行安排独立只读检查者。施工队与用户仍分别负责草稿和生效裁定。 |
| commands／入口 | 用 `$pmo` 加自然语言进入初始化、续接、对账和回溯。 |

按 [通则卷 #20／#21](通则卷.md) 把实际降级与替代写入部署回执。触及承重执法的降级，按 #7 取得用户显式接受并记录后，部署方可生效。技能出现在 Codex 列表中只证明加载成功。

| #20 执法项 | 手工替代 |
| --- | --- |
| 会话启动 | 进入 PMO 工作先读项目 `governance/状态板.md`，核当前阶段、身份指针和待裁项。 |
| 写入权限 | 按权-01 和 #16 核对目标层及授予，交付物先写草稿，环境级受保护字段经用户通道。 |
| 产出物头部 | 门禁前按 #4、#6 核类型、版本、上游 ID 与实物指针。 |
| 图一致性 | 从登记图核出处、层级和双向覆盖，语义判断依 #19 裁定。 |
| 生效状态 | 逐件对照已生效状态、对应决策记录及授予范围。 |
| 决策记录写入 | 只在 #7 第三步按用户裁定记载，留原话和关联项，由检查者对照证据。 |

## 独立检查者

给独立检查者单开只读会话，只交待核产物、对应判据和必要上游，不带入生产对话或生产者结论。使用 Codex CLI 时，可在目标项目根目录新启会话：

```sh
codex --sandbox read-only --ask-for-approval never --disable memories
```

只读沙箱约束 shell。检查时还须确保可用工具不具有项目写入能力，或由独立人工检查者承担。同一生产会话中的子代理继承该会话的权限。校验结论交回用户裁定，检查者只提交证据和发现。 [Codex 子代理与权限](https://developers.openai.com/codex/subagents)
