# ZCode 宿主绑定

PMO 由 `pmo@pmo-local` 插件提供。安装并启用后，在 ZCode 输入框的 `/` 菜单中从「技能」选择 `pmo-zcode`，再说明要初始化、接续或评审哪个项目。插件限定名为 `pmo:pmo-zcode`。卷册和模板从已安装的 `skills/pmo-zcode/` 定位，项目状态板和交付物从当前产品项目根目录定位。

启动卡探测宿主时，核对「设置 → 技能」的「Plugin 技能」中能找到 `pmo-zcode`，并确认同一安装副本含 OO 指引且流程卷的指针可读。部署回执记录实际安装路径、安装范围、ZCode 版本、插件版本、约束包来源提交或快照和文件核验结果。项目使用时按权-01 只读，更新走插件市场。用户范围安装时，每个产品项目仍按自己的状态板与授予记录推进。

| #20 组件 | ZCode 实态 |
| --- | --- |
| skills／方法 | 插件携带 PMO 入口、卷册、OO 可选指引和模板。 |
| rules／声明 | 规则随技能加载。项目按实际能力登记常驻声明的降级。 |
| commands／入口 | 通过 `/` 菜单选 `pmo-zcode`，由技能路由到用户指定的动作。 |
| agents／角色 | 项目安排独立检查者，保留只读、分离、不共享生产上下文的要求。 |
| hooks／强制 | 本插件无强制钩子，机械核验按下文记录实际替代。 |

按 [通则卷 #20／#21](通则卷.md) 核验状态板续接、四层写边界、产出物头部、图出处及覆盖、已生效物的决策记录、裁定写入通道。部署回执按项记录宿主能力及手工替代。触及承重执法的降级，先按 #7 由用户显式接受手工替代，再授予项目治理生效。

检查者另开只读环境或由独立人工承担，只接收待核产物、对应判据和必要的上游证据。安排时确认会话和可用工具均无项目写入权。检查结论交用户裁定。 [ZCode 插件文档](https://zcode.z.ai/cn/docs/plugin)
